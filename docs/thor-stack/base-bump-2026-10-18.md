## The fused-draft-decode collision with upstream work

0.32.0 landed its own fused-draft machinery for the **trtllm-gen** decode
path: a `supports_draft_decode_metadata_update` grant
(`flashinfer_trtllm_api_decode_kernel == TRTLLM_GEN and not use_dcp`) and a
**stub** `update_draft_decode_metadata` (their path needs no per-step plan
update). Our patch's three collision points and the resolution:

1. **The `__init__` grant** — ours used to overwrite upstream's. Now
   **OR-ed**: upstream's trtllm-gen grant `or` our FI-native grant
   (`enable_cuda_graph and dcp_world_size == 1 and not
   use_trtllm_decode_attention`).
2. **The method itself** — the patch now **replaces the upstream stub body**
   with the real FI-native plan advance (previously it inserted a new
   method). The `isinstance(metadata.decode, FIDecode)` guard keeps the two
   paths disjoint: trtllm-gen metadata flows through as a no-op, exactly
   like upstream's stub.
3. **The trailing anchor** — `use_cascade_attention` is gone from the
   builder (moved/removed upstream); hunks re-anchored on the stub and the
   `class FlashInferImpl` boundary. The module-level
   `_advance_fi_decode_plan_kernel` still appends at EOF.

Also gone in 0.32.0: `v1/worker/gpu/spec_decode/autoregressive/` (the
pre-0.29.1 home of 49652's target) — the Dockerfile smoke-test `touched`
list was updated to the current patched-file set (16 entries).

## Post-bump e2e validation: the drafter-acceptance regression, found & fixed (2026-10-18, evening)

The 0–32K single-repeat `bench ab` (official vs Mjolnir, both on 0.32.0)
caught MTP acceptance collapsing beyond draft position 0 on the Mjolnir leg:
**4.1 → 2.04 tokens/step**, per-position 0.82/**0.17**/0.04/0.01/0.00 (the
official leg reproduced history exactly: 2.96, 0.82/0.63/0.50 at K=3).
Prefill/TTFT were unaffected; decode was depressed by the broken drafter.

**Probe matrix** (6-run `bench perf --depths 0` per probe, spec counters):

| probe | graphs | draft-metadata path | tokens/step | per-position |
|---|---|---|---|---|
| A/B leg 2 (broken) | FULL draft graphs | fused (built once at capture) | 2.04 | 0.82/0.17/0.04/0.01/0.00 |
| `--enforce-eager` | none | fused, built per cycle | 4.05 | 0.85/0.70/0.57/0.51/0.42 |
| `MJOLNIR_ATTN_FUSED_DRAFT=0` | target graphs, draft unfused | rebuilt every draft step | 3.73 | 0.84/0.66/0.52/0.40/0.31 |

fp6 KV, the calibration scales and the T5 no-op `update_draft_decode_metadata`
are all innocent (the eager probe runs the identical fp6 path and scores
4.05). **Root cause:** 0.32.0's `_fused_multi_step_decode` returns before
`_build_uniform_attn_metadata` on the FULL-graph path (0.31.x built it
unconditionally), so the T5 split-KV work plan — host-computed in `build()`
from seq_lens into persistent buffers — stays baked at capture-time seq_lens;
every replayed draft step attends a truncated context. Draft *prefill*
(position 0) and the target's PIECEWISE attention build per cycle, which is
why only positions 1+ died.

**Fix:** `thor-fused-draft-t5-plan-refresh.patch` — the FULL branch rebuilds
the draft metadata before `run_fullgraph` (the returned metadata is unused;
the side effect refreshes the persistent plan buffers the graph reads — the
0.31.x contract, at the same per-cycle host cost 0.31.x always paid).
Registered in `PATCH_ORDER`, sentinel in `verify_patches.py` (13 fixes now),
Dockerfile `touched` list at 17. Fix probe (`docker commit` of the patched
speculator, `v0.32.0-t5fix`): fusion + FULL graphs + fp6 score
**3.40 tokens/step, per-position 0.77/0.59/0.43/0.34/0.27** — healthy decay,
+67% acceptance over the broken run (the residual gap to the unfused 3.73 is
within the 6-sample probe noise; the full A/B re-run is the tight number).
